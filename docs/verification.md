# 构建与运行验证

## 构建环境

- Windows 10.0.19045 x64
- MSVC 19.51.36257（Visual Studio 2026）
- CMake 4.3.1
- Qt 6.8.3 MSVC2022 x64 静态版（`-static -static-runtime`）
  - `D:\Qt\6.8.3\msvc2022_64_static`

## 静态单文件构建

- 构建目录：`build/build-static`
- 产物：`dist/BigA.exe`，17,264,640 字节
- CMake 自动采用 `/MT`，并嵌入 qwindows 平台插件、现代 Windows 样式以及
  GIF/ICO/JPEG 图片插件。
- `dumpbin /DEPENDENTS` 仅列出 Windows 系统 DLL，没有 `Qt6*.dll`、
  `VCRUNTIME*.dll` 或 `MSVCP*.dll`。
- 将单个 exe 复制到仅含该文件的空目录后启动成功，托盘图标正常注册。
- 静态版本成功读取 JPEG 格式的 `current-image.img`，窗口尺寸为图片原始
  200×100。

## 已执行

- Debug / Release 均无警告编译、链接通过。
- 启动：3×3 白点位于主屏中心；不抢 Notepad 前台焦点。
- 单实例：启动第二个 `BigA.exe` 后进程数保持 1，第二个进程直接退出。
- 设置窗口：720px 宽、约 702px 高；无边框、仅右上角“×”；主屏居中；四个分组完整显示。
- 设置关闭：配置写入 `user-config.json`，无 `.tmp` 残留；白点大小立即从 3 变为 7，窗口变为 7×7。
- 键盘捕获：小键盘扫描码 0x4C 捕获为“小键盘 5”。
- 鼠标捕获：中键、XButton1、滚轮上分别捕获为“鼠标中键”“鼠标侧键1”“滚轮上”。
- 重复绑定：捕获已绑定键时弹出“该键已绑定到 一号武器键 1，是否解绑并重新绑定？”，取消后继续捕获。
- Esc：取消捕获，原值恢复。
- 键入框右键：清空为“未绑定”，不进入捕获。
- 容量框：点击全选，按数字 8 后立即写入并失焦。
- 参数框：数字 7 替换全选值；Enter 提交；清空后点击其他控件恢复 7。
- 右键状态机（设置窗口在前台时）：
  - 延迟 500ms，按住 900ms 后隐藏，松开恢复；
  - 容量 0：不隐藏；
  - 刀：隐藏；
  - 状态 = 容量 - 1：不隐藏；
  - 其他：隐藏。
- 容量+1：运行时容量从 2 变 3，3 秒防抖后配置保存为 3。
- 图片启动：`current-image.img` 内的 120×90 透明 PNG 按原始尺寸显示，四周透明；
  3000×2000 PNG 位于 `(-220, -280)`，即仍以 2560×1440 主屏中心对齐并允许超出屏幕。
- 图片按内容识别：文件扩展名为 `.img` 仍可读取 PNG。

## 测试环境限制

本次自动化会话会把直接从 `E:\workspace\biga` 内启动的进程降为 Low Integrity。
Windows 不允许这类进程注册通知区域图标，因此直接运行工作区内的 exe 时托盘不出现；
把同一个 exe 复制到工作区外后进程为 High Integrity，托盘图标和右键菜单均正常。

Windows 还会按完整性/前台策略过滤部分后台 `WM_INPUT` 投递，因此“另一个普通
应用位于前台时的全局热键”未能在此会话内做最终验证；使用最小 Win32
`RIDEV_INPUTSINK` 探针复现了相同行为。工程使用标准 `WM_INPUT + RIDEV_INPUTSINK`
路径，未添加低层键盘钩子替代实现。在普通桌面会话（应用与前台程序同一完整性
级别）中应按 Windows Raw Input 语义工作。
